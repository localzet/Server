# localzet/server: работа с кодом

Семейство: Localzet Server / Cluster. Общая принадлежность не разрешает перенос кода или публикацию закрытых компонентов.

## Рабочий цикл

Общение — по-русски; комментарии в коде — краткие английские. Перед изменениями прочитай ближайшие вложенные AGENTS.md, проверь ветку, diff и индекс. Сохраняй чужой WIP; добавляй в commit только свои файлы/изменения. Коммиты — Conventional Commits, author и committer Ivan Zorin <creator@localzet.com>. Push и deployment выполняй только в рамках текущего разрешения пользователя; этот файл сам по себе их не разрешает.

Начинай с затронутого entry point, вызывающего кода и тестов, а не чтения всего репозитория. Используй rg с узким путём; исключай зависимости и build-артефакты. Для сложного изменения кратко зафиксируй границы и план; выполняй по одному проверяемому шагу. Не повторяй успешные проверки без изменения кода или новой причины. Реальную неоднозначность публичного контракта уточняй; обычные локальные решения принимай самостоятельно.

Следуй стандартам языка, SOLID/DRY/KISS/YAGNI и текущим границам модулей. Сначала используй существующий механизм; не вводи новую абстракцию, зависимость, сервис или слой без конкретной необходимости. Сохраняй совместимость API и форматов; изменения схем/протоколов сопровождай миграцией и проверкой старых клиентов. Значимый архитектурный долг объясняй отдельно, без попутного переписывания проекта.

Проверяй права на сервере, валидацию входа, таймауты, освобождение ресурсов и обработку ошибок; внешние побочные эффекты делай ограниченными и повторяемыми там, где это необходимо. Не читай и не печатай секреты, env, дампы и пользовательские данные без необходимости. Не меняй production, лицензии, исходное авторство или visibility репозитория попутно.

Документацию сверяй с реализацией и выполняемым примером: README, типы и сигнатуры сами по себе не подтверждают поведение. Для библиотек EN + RU, продуктов RU + EN, исследований Axiom — RU. Не выдавай импортированный текст, проектное намерение или green build за полную проверку продукта.

Перед завершением проверь свой diff, исполни подходящие тесты и проверки изменённого слоя. Для исправления поведения добавь регрессионный тест; для простого текста достаточно проверки ссылок/формата. В отчёте укажи результат, выполненные проверки и существенные ограничения; отличай локальную проверку, CI и production.

## Серверный цикл

Сохраняй неблокирующий I/O, process lifecycle, очистку Timer/listeners и backpressure. Тестируй framing на частичных/объединённых пакетах, разрыв соединения и shutdown. Не меняй число процессов, сигналы и сетевые defaults без проверки совместимости.

## Карта проекта и проверки

Код и опорные каталоги: `src/`, `tests/`.

Точки входа/ядро: `Server.php`, `ServerAbstract.php`, `Timer.php`, `Helpers.php`.

Опорные файлы: `README.md`, `README.ru.md`, `.github/CONTRIBUTING.md`, `.github/SECURITY.md`.

`composer.json`: localzet/server; runtime ">=8.1".

Объявленные проверки: `composer run lint`, `composer run test`, `composer run analyze`, `composer run test:integration`, `composer run check`, `composer run test:all`, `composer run test:revolt`, `composer run test:gateway`, `composer run test:fuzz`, `composer run test:memory`, `composer run release:audit`, `composer benchmark -- --smoke`. Основная CI проверяет Linux/PHP 8.1–8.5 на едином наборе dev-зависимостей; еженедельная задача проверяет последние допустимые версии.

Команды выше найдены в манифестах, а не проверены запуском. Перед выполнением прочитай их реализацию, нужные переменные и внешние зависимости. Не запускай нагрузочные, сетевые, deploy/migration-задачи или полный train как обычный smoke test.

### Ограничения реализации

PHP: соблюдай PSR и ограничения PHP из composer.json; публичные namespace/сигнатуры и PSR-4 — контракт. Не редактируй vendor и сгенерированные классы. Проверяй nullability, исключения и совместимость зависимостей.

## Границы семейства

Server, Cluster и Rust-адаптация имеют собственные реализации. Не копируй PHP API механически в Rust; проверяй семантику lifecycle, delivery, таймаутов и исключений в конкретном компоненте. Публичный wire format меняй с учётом существующих клиентов.
